# gmemo

Googleに接続して、MarkdownメモやファイルをGoogle Driveに保存するツールです。ブラウザで動くHTMLで、独自のバックエンド、APIキー、クライアントシークレットは使いません。外部から読み込むスクリプトはGoogle公式の認証ライブラリだけです。

- **index.html**：人向け。フォルダ・ファイル一覧、Markdown編集・簡易プレビュー、複数ファイル添付、ファイルのみの保存、フォルダ作成。
- **ai.html**：AI向けの装飾なしHTML。標準の入力欄・ボタン・結果だけを表示します。KEY（ファイルID／URL）で取得、ダウンロード、Markdown更新、ファイルの差し替え・新規保存。Drive全体の一覧は取得しません。結果は小さなJSONで表示します。
- **GMEMO.MD**：AIに渡す操作説明書。

両HTMLはそれぞれ単独で動作します。同じ場所に置くと画面間のリンクと説明書のダウンロードを使えます。

## 起動

```sh
python3 -m http.server 8000 --bind localhost
```

人向け画面は <http://localhost:8000/>、AI用画面は <http://localhost:8000/ai.html> を開きます。`file://` でHTMLを直接開くとGoogle認証はできません。公開する場合はHTTPSで配信してください。ビルドやnpmインストールは不要です。

## 初期設定（開発者が初回だけ実施）

1. [Google Cloud Console](https://console.cloud.google.com/)でプロジェクトを作成し、**Google Drive API**を有効化します。
2. Google Auth Platformでブランド情報、対象ユーザー、同意画面を設定します。テスト中は利用するアカウントをテストユーザーに登録します。
3. データアクセスに `https://www.googleapis.com/auth/drive` を登録します。
4. OAuthクライアントを**ウェブアプリケーション**として2つ作成します。通常画面用の `GMEMO` は「Use this client for an AI-powered agent」をチェックせず、AI用の `GMEMO AI` はチェックします。[Googleの案内](https://developers.google.com/workspace/guides/create-credentials#web-application)に従って、人向けとAI向けのIDを分けます。承認済みのJavaScript生成元に `http://localhost` と `http://localhost:8000` を登録します。別のポートや配信先を使う場合は、その生成元も登録します。
5. 通常画面の「初期設定」に通常用IDを、AI用画面の「初期設定」にAI用IDを貼り付けます。IDは別々に保持します。初期フォルダー名も設定できます。未入力なら `gmemo` になり、このフォルダー設定は両画面で共有します。
6. 「Googleに接続」を押し、Googleのログイン画面でアカウントを選択し、アクセスを許可します。

配布時には `index.html` の `DEFAULT_CLIENT_ID` に通常用ID、`DEFAULT_AI_CLIENT_ID` にAI用IDを入れてから `node scripts/build-ai.mjs` を実行することもできます。その場合、利用者がIDを設定する必要はありません。クライアントIDは公開可能な識別子です。クライアントシークレットは一切入れないでください。

既存の共有ファイルの閲覧・編集に対応するため、Drive全体の読み書き権限を使用します。これはGoogleの制限付きスコープです。一般公開時のOAuth審査などは[Googleの公式説明](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)を確認してください。

## 保存と共有

初期設定のフォルダー名（未入力なら `gmemo`）を使い、接続時にマイドライブ直下の同名フォルダーを検索します。なければ作成し、あれば再利用します。同名フォルダーが複数ある場合は、誤った場所を選ばずエラーにします。画面は初期フォルダーから始まり、マイドライブ直下・共有アイテム・共有ドライブの一覧は表示しません。

閲覧・保存・ダウンロード・ファイル更新は、その初期フォルダーと子孫に限ります。URL、ID、ショートカットの指定でも範囲外は拒否します。通常画面とAI用画面の初期フォルダー設定は共通で、変更後は再接続が必要です。既存ファイルは自動移動しません。以前の保存場所を使うにはDrive側で初期フォルダーの中へ移動してください。必要な共有設定はDrive側で初期フォルダーやその中のファイルに行います。

AI、Photo、Music、メモなどの初期フォルダは自動作成しません。「＋ フォルダ」で必要な場所に作成してください。

メモはUTF-8の `.md` として保存します。一覧でMarkdownのファイル名または「編集」を押すと、下のメモ欄に本文を読み込み、編集モードに切り替えます。「変更を保存」で同じファイルを更新します。ダウンロードはエディタの「↓ .md」から明示的に行います。添付は同じフォルダに個別のファイルとして保存し、本文にはDriveリンクを追加します。タイトル・本文を空にすれば、ファイルだけを登録できます。添付の共有範囲は保存先フォルダの権限に従います。

## AIへの渡し方

1. 先に **AI用画面 `ai.html` を開きます**。初回は「初期設定」でAI用クライアントIDを登録します。
2. 「Googleに接続」で接続を済ませ、アカウントが表示された状態で **そのタブを開いたままにします**。認証トークンはタブごとに保持するので、人向け画面が接続済みでもAI用画面では別に接続が必要です。
3. 通常画面でメモを保存した後「AI用URLをコピー」を押します。ファイルやフォルダの行にある「URL」からも取得できます。
4. AIに `GMEMO.MD` とコピーしたURLを渡し、「AI用画面は接続済みです」と添えて作業を指示します。AIは接続済みタブのKEY欄を使うので、ページの再読み込みは不要です。

例：

> GMEMO.MDを読んで、このURLのメモに作業結果を追記して同じファイルに保存してください：…/ai.html#file=…

> GMEMO.MDを読んで、このURLの資料をダウンロードして編集し、元ファイルを更新してください：…/ai.html#file=…

ブラウザ操作・ファイルの読み書き・アップロードができるAI環境が必要です。この作業中のCodex環境では、通常画面での保存をユーザーに確認いただき、AI用画面からの実ファイル取得、および仕様書Markdownの新規保存・再取得を確認しました。ファイル差し替えは実データで未検証です。Codex CLI等、ブラウザ操作機能がない環境では説明書だけで操作できるようにはなりません。[公式のブラウザ機能説明](https://learn.chatgpt.com/docs/browser?surface=app)も参照してください。

AI用画面を分ける目的は、指定ファイルだけを扱い、画面情報と操作を減らすことです。初期フォルダー外の操作もツール内で拒否しますが、GoogleのOAuth権限自体をフォルダー単位に狭めるものではありません。MCPサーバーや外部向けAPIは追加していません。

## 保持される情報と制限

- アクセストークンはメモリだけに保持し、ページを閉じると消えます。期限切れは「再接続」で復帰します。更新トークンは保持しません。
- クライアントIDと本文の下書きはブラウザのlocalStorageに保存します。端末上の平文データです。人向け／AI用の下書きは分けています。
- 再読込後の下書きは新規メモとして扱います。既存ファイルの更新には、そのファイルを再取得してください。
- 添付の実体とアップロード再開情報はメモリだけです。通信失敗時は同じ画面で再保存して再開できます。再読込や接続解除は再開情報を失うため、途中のアップロードがあると重複の可能性があります。
- 保存はファイルごとです。途中で失敗しても、それまでに成功したファイルはDriveに残ります。自動削除やロールバックはしません。
- Markdown読込は5MBまで。添付は8MiB単位の再開可能アップロードを使います。バイナリダウンロードはブラウザのメモリを使います。Driveの容量・ファイルサイズ上限・組織ポリシーに従います。
- 同時編集の自動マージやロックはありません。複数人で同じメモを更新すると後の保存で上書きされます。
- プレビューは簡易Markdownです。HTMLや実行可能なURLを解釈せず、外部画像も自動読込しません。

## 開発・確認

```sh
node scripts/build-ai.mjs
node scripts/build-ai.mjs --check
node --test tests/workflows.test.cjs
```

`ai.html` は `index.html` から生成します。認証・権限確認・アップロード処理は同じソースを使い、AI用の画面と動作モードを生成時に追加します。変更は `index.html` と `scripts/build-ai.mjs` に行い、生成済み `ai.html` も更新してください。

テストはGoogle APIを模擬し、ファイルのみの保存、Markdownと添付、初期フォルダー内のページングと読み取り専用権限、初期フォルダーの作成・再利用と範囲外アクセスの拒否、通信失敗後の再開、AIによる指定ファイル取得と更新、安全なプレビューを確認します。実際のGoogle認証、Googleグループ経由の権限、ブラウザとDrive間のアップロードは、利用するGoogle Cloudプロジェクトでの確認が必要です。
